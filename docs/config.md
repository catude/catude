# Config: the settings of every Claude app

The **Config** tab (tab `2`) lists the configuration file of every Claude app found on the machine. Choose a
file on the left; on the right appear **every documented setting** of that app (the ones the file sets,
marked `●` and first in each category, and all the others with their default), grouped by category, with
what each does, its allowed values, its default and which files may hold it.

## How the apps relate

This is the part people get wrong, so it is shown in the tab itself:

| | Reads |
|---|---|
| **Claude Code** in the terminal and IDE extensions | its own files only: `settings.json` (yours, the project's, your local one, the organisation's policy) and `~/.claude.json`. It does **not** read Claude Desktop's file |
| The **Code tab inside Claude Desktop** | the same Claude Code files (`settings.json`, `CLAUDE.md`, skills, `~/.claude.json`, `.mcp.json`) **plus** the MCP servers of Claude Desktop's file |
| **Claude Desktop** chat | its own `claude_desktop_config.json` |
| Both | connectors, skills and plugins enabled on claude.ai arrive through your **account**, not through files |

So an MCP server added to Claude Desktop does not appear in Claude Code in the terminal, and the other way
round. `claude mcp add-from-claude-desktop` imports them, but only on macOS and WSL.

Source: Claude Code documentation (`desktop`, `mcp`, `settings-reference`, `claude-directory`).

## Files listed

- **Claude Code**: your settings, this project's shared settings, your private settings for this project,
  every extra configuration folder (`CLAUDE_CONFIG_DIR`), the organisation policy (read-only) and the
  global options of `~/.claude.json` (IDE connection, copy on select, diff tool…).
- **Claude Desktop**: one entry per install found: the installer version, the Microsoft Store version (the
  copy the Store app really reads, under `%LOCALAPPDATA%\Packages\…`), Claude-Data, macOS and Linux (`~/.config/Claude/`).
  Its **organisation policies** (registry `HKLM/HKCU\SOFTWARE\Policies\Claude` on Windows,
  `/etc/claude-desktop/managed-settings.json` on Linux) are listed read-only with the values set on this machine.
  Other Claude Desktop options live inside the app (Settings) and are not documented as a file.

## Effective settings

**Effective settings**, listed after Claude Code's files, answers "which value does Claude Code really use
here, and why?". For every key set in any of this project's Claude Code settings files it shows the value
that wins and the file it comes from; select a key to see what it wins over. It follows the rules of the
[settings documentation](https://code.claude.com/docs/en/settings#settings-precedence):

- a key set in several files takes the value of the highest one: organisation policy, then this project
  (only you), then this project (shared), then your settings;
- lists such as `permissions.allow` combine the lists of every file, without duplicates;
- `fallbackModel` never combines: the whole list comes from the highest file that sets it;
- `modelPicker` is read only from the organisation policy and your settings, so a project file cannot
  change it; `availableModels` from the policy applies as it is.

Command-line flags (`--settings`, `--model`…) apply to one session and are not shown. The view is read-only:
change a value in the file it comes from. Secrets stay masked.

## Where the list comes from

`internal/claudecfg/reference.json`, generated by `scripts/build-settings.mjs` from Anthropic's documentation:
[settings reference](https://code.claude.com/docs/en/settings-reference) (settings.json and global
options), [environment variables](https://code.claude.com/docs/en/env-vars), [Claude Desktop enterprise
configuration](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop)
and its [configuration reference](https://claude.com/docs/third-party/claude-desktop/configuration), and the
MCP documentation for `claude_desktop_config.json`. Keys that only appear in the published JSON schema are
marked as such; deprecated ones are shown as `(old)`. Settings that a file cannot hold (for example
managed-only keys in your user file) are not offered there.

`✓` exists · `○` not created yet (setting a value creates it) · `●` read-only.

## Changing values

| Key | |
|---|---|
| `↑` `↓` · `enter` | choose a file · open its values |
| `enter` on a value | type a new value |
| `space` | switch a yes/no value · move to the next documented value (for example `effortLevel`: low → medium → high → xhigh) |
| `d` | remove the setting from the file: the app goes back to its default |
| `a` | show only what the file sets / every documented setting |
| `/` | search names, values, descriptions and categories |
| `e` | open the whole file in your editor (for lists, hooks, MCP servers and anything structural) |
| `esc` | back to the list of files |

Environment variables appear as their own category: they are written under `"env"` in the settings file.
A yes/no variable is stored as `"1"` and switched off by removing it, because some variables treat any
value, even `"0"`, as on. Variables that hold credentials (keys, tokens, secrets) are listed but never typed
in here.

## Safety

- A backup is written to `<user cache>/catude/backups/` before every change.
- The file keeps its key order and every value you did not touch; the result is parsed again before it
  replaces the original, and a file that is not valid JSON is never overwritten.
- Secrets are masked and cannot be changed inline; a value that looks like a secret is refused, because
  secrets belong in environment variables.
- Hooks, headers, credentials and lists are not editable inline: they open in your editor instead.
- `permissions.defaultMode` cannot be set to `bypassPermissions` from here.
- Organisation policies are read-only. `~/.claude.json` is changed only for its documented options and only
  while no Claude Code or Claude Desktop process runs (they rewrite the file and would undo the change);
  otherwise use `/config` inside Claude Code.

After a change the status bar says what must be restarted: new Claude Code sessions, or Claude Desktop
(quit it completely and open it again).

## Presets

Press `p` in the Config tab for **configuration presets**: small groups of settings for one goal, such as no
telemetry, protecting `.env` files, a lower-cost default model, sandboxed Bash, asking before `git push`, desktop
notifications, or the settings Trail of Bits publishes. There are 30 of them.

- Each one comes from a public source, quoted word for word: Anthropic's documentation, Anthropic's example
  settings, or the organisation that published it. The panel shows the sources and the quotes.
- Each one shows what it would change in the file selected on the left (`+ key = value`, and what it was before),
  and `already so` for what your file already has.
- Lists such as `permissions.deny` keep your items and get the new ones; objects are merged key by key.
- Risk: `✓` low, `▲` medium or high, with the reason (for example, turning telemetry off also stops feature flags).
- Presets that do not apply to your system are greyed out (the sandbox does not run on native Windows).
- `t` filters by tag, `/` searches, `enter` twice applies (after a backup), `esc` goes back.

The list lives in `internal/claudecfg/config-presets.json`. A test checks that every key is a documented setting
and that every preset has a source with a quote. Pull requests with new presets are welcome on the same terms.
